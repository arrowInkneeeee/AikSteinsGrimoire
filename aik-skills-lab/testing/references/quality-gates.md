# 质量门禁标准

## 准入标准（开发完成）

进入测试阶段前必须满足：

- [ ] 单元测试通过率 > 90%
- [ ] 行覆盖率 > 60%
- [ ] 分支覆盖率 > 50%
- [ ] 无 P0/P1 级别缺陷

## 准出标准（可发布）

发布前必须满足：

- [ ] 所有测试通过
- [ ] 行覆盖率 > 70%
- [ ] 分支覆盖率 > 60%
- [ ] 接口文档已交付前端
- [ ] 无未修复的高优先级缺陷

## 覆盖率阈值调整策略

```
如果初次覆盖率 < 40%：
  → 设定阈值 40%/30%，逐步提高
如果初次覆盖率 40-60%：
  → 设定阈值 60%/50%
如果初次覆盖率 > 60%：
  → 设定阈值 70%/60%
```

## 测试补充策略

分析未覆盖代码时的决策：

| 未覆盖代码类型 | 处理方式 |
|--------------|---------|
| 简单 getter/setter | 忽略 |
| 核心业务逻辑 | 补充测试 |
| 异常分支 | 评估必要性 |
| 废弃代码 | 建议删除 |

## 测试优先级

| 优先级 | 范围 | 说明 |
|--------|------|------|
| P0 | 核心业务流程 | 下单、支付等 |
| P1 | 常用功能 | 查询、列表等 |
| P2 | 管理功能 | 统计、导出等 |

## 持续改进度量

### 测试效率

- 测试代码/生产代码比例
- 测试执行时间
- 缺陷发现阶段分布

### 测试质量

- 测试通过率趋势
- 覆盖率趋势
- 生产缺陷密度
