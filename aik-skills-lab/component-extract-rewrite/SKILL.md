# component-extract-rewrite

组件萃取与复写全流程技能，覆盖代码分析、组件知识萃取、脱敏复写和完整流水线执行。

## 子命令

### analyze

对用户指定的代码范围进行6维深度分析，产出结构化分析报告。

**触发条件**：用户说"分析这个类"、"分析这个包"、"提取可复用逻辑"

**输入**：
- 源项目路径（纯英文路径）
- 代码范围（类名或包路径）
- 前置条件：源项目已通过 `gitnexus analyze` 构建索引

**输出**：
- 结构化分析报告（6维分析）

**执行步骤**：
1. 加载 `references/coupling-patterns.md` 耦合模式参考
2. 确认源项目已构建 gitnexus 索引
3. 对指定代码范围进行6维分析：
   - **架构模式**：识别可复用的架构模式（策略模式、模板方法等）
   - **业务耦合点**：识别与业务逻辑耦合的代码（硬编码、业务规则）
   - **数据依赖**：识别数据库表、外部服务依赖
   - **敏感数据**：识别需要脱敏的字段（手机号、身份证等）
   - **通用性评估**：评估代码的通用化潜力
   - **依赖关系**：识别类间依赖和外部依赖
4. 输出结构化分析报告

---

### extract

从源项目萃取组件知识，产出结构化组件手册。

**触发条件**：用户说"萃取组件"、"提取组件手册"、"生成组件文档"

**输入**：
- 源项目路径（纯英文路径）
- 组件范围（类名或包路径）
- 前置条件：源项目为 Git 仓库，Node.js >= v20.17.0

**输出**：
- 组件知识手册（Markdown格式，10章结构）

**执行步骤**：
1. 加载 `references/component-manual-structure.md` 组件手册结构定义
2. 加载 `references/grimoire-location-chain.md` 定位链规则
3. 确定产出路径（AIK_GRIMOIRE_HOME 定位链）
4. 按10章结构生成组件手册：
   - 第1章：组件概述（定位、适用场景、不适用场景）
   - 第2章：架构设计（核心模式、类图、时序图）
   - 第3章：核心接口（API定义、参数说明）
   - 第4章：数据模型（实体定义、关系图）
   - 第5章：配置说明（配置项、默认值）
   - 第6章：扩展点（SPI接口、自定义策略）
   - 第7章：业务耦合清单（需要脱敏的点）
   - 第8章：依赖清单（Maven依赖、外部服务）
   - 第9章：测试策略（测试用例、Mock方案）
   - 第10章：迁移指南（接入步骤、常见问题）
5. 保存组件手册至目标路径

**人机协作节点**：
- 检查点1：确认组件范围是否正确
- 检查点2：确认业务耦合点是否完整
- 检查点3：确认手册内容是否准确

### rewrite

基于组件知识手册，将源代码复写为脱敏、标准化的代码。

**触发条件**：用户说"复写组件"、"代码脱敏"、"标准化复写"

**输入**：
- 组件知识手册（来自 extract 子命令）
- 目标项目路径
- 前置条件：目标项目已初始化通用组件（Result/BaseEntity等）

**输出**：
- 脱敏后的标准化代码（遵循 aIk-coding-style）

**执行步骤**：
1. 加载 `references/rewriter-delivery-spec.md` 交付规范
2. 加载 `references/desensitization-patterns.md` 脱敏模式
3. 读取组件知识手册
4. 按3层审查流程复写代码：
   - **第1层：风格审查** — 确保符合 aIk-coding-style
   - **第2层：质量审查** — 确保无N+1、空指针等问题
   - **第3层：安全审查** — 确保敏感数据已脱敏
5. 脱敏处理：
   - 业务术语替换为通用术语
   - 硬编码值提取为配置项
   - 敏感字段脱敏（手机号→phoneNumber）
6. 生成标准化代码文件
7. 保存至目标项目

**人机协作节点**：
- 检查点1：确认脱敏规则是否正确
- 检查点2：确认复写代码是否符合规范
- 检查点3：确认目标项目是否能正常编译

### full-pipeline

完整流水线：萃取 + 复写 + 入库。

**触发条件**：用户说"完整萃取复写"、"把这个组件迁移到新项目"

**输入**：
- 源项目路径
- 组件范围
- 目标项目路径（可选）

**输出**：
- 组件知识手册
- 脱敏后的标准化代码
- 入库记录（更新索引）

**执行步骤**：
1. 加载 `references/grimoire-location-chain.md` 定位链和4种内容类型
2. 执行 `analyze` → 6维代码分析
3. 执行 `extract` → 产出组件知识手册
4. **【人机协作】** 确认手册内容
5. 执行 `rewrite` → 脱敏复写标准化代码
6. **【人机协作】** 确认复写代码
7. 确定内容类型路由（NOTE/COMPONENT/SOLUTION/CODE）
8. 按路径解析规则存放产出物
9. 更新索引文件
10. 输出完整流水线报告

**内容类型路由**：
| 类型 | 说明 | 存放路径 |
|------|------|---------|
| NOTE | 学习笔记、URL资料整理 | scrolls/ |
| COMPONENT | 组件知识手册 | components/{组件名}/ |
| SOLUTION | 解决方案 | solutions/{方案名}/ |
| CODE | 标准化代码 | components/{组件名}/code/ |

## 输入契约

| 输入项 | 路径/来源 | 必须 | 降级策略 |
|--------|----------|------|---------|
| 源项目路径 | 用户指定 | 是（analyze/extract） | 无 |
| 组件范围 | 用户指定（类名/包路径） | 是 | 无 |
| 组件知识手册 | extract 子命令产出 | 是（rewrite） | 无 |
| 目标项目路径 | 用户指定 | 否（rewrite/full-pipeline） | 当前项目 |
| gitnexus索引 | 源项目已执行 `gitnexus analyze` | 是（analyze） | 提示用户先构建索引 |

## 输出契约

| 输出项 | 路径 | 格式 |
|--------|------|------|
| 分析报告 | 内联输出 | Markdown |
| 组件手册 | `{AIK_GRIMOIRE_HOME}/components/{组件名}/manual.md` | Markdown |
| 标准化代码 | `{目标项目}/src/main/java/` | Java源文件 |

## 工作流上下文

**上游技能**：无（独立技能，可由用户随时触发）

**下游技能**：
- `code-review`：对复写后的代码进行审查
- `code-implementation`：在复写代码基础上扩展功能

## 质量门禁

| 检查点 | 条件 | 动作 |
|--------|------|------|
| 索引检查 | gitnexus 索引已构建 | 继续，否则提示构建 |
| 手册确认 | 用户确认手册内容 | 继续 |
| 代码确认 | 用户确认复写代码 | 继续 |
| 编译检查 | 目标项目可编译 | 继续 |

## 约束

- 源项目路径必须为纯英文（避免编码问题）
- 所有复写代码必须遵循 `aIk-coding-style` 规范
- 敏感数据必须脱敏处理
- 业务术语必须替换为通用术语
- 组件手册使用10章标准结构
- 产出路径遵循 AIK_GRIMOIRE_HOME 定位链
