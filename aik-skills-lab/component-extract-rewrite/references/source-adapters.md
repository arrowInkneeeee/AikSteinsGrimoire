# 源适配器（source adapters）

> 本文件定义 `component-extract-rewrite` 支持的四类知识源：**外部项目 / 工作空间文档 / 网站页面 / 粘贴文本**。
> 所有适配器都是**只读**：不修改、不移动、不删除源；只采集信息并在报告里记录来源。
> 权威方案：`grimoire-files/plans/knowledge-ingestion-rework.md` §5.1。

## 0. 统一契约

每个源在 `ingest-manifest.json` 里独立记录：

```json
{
  "type": "local-repo | workspace-doc | web-page | pasted-text",
  "ref": "路径 / URL / 用户粘贴标识",
  "fetchedAt": "ISO-8601",
  "title": "可选",
  "site": "可选（网页）",
  "license": "可选（网页/外部文档）",
  "notes": "采集限制/降级说明"
}
```

原则：

1. **只读源**；落盘只写魔典（`$GRIMOIRE`），不写源项目/源目录。
2. **溯源**：每条知识必须能回答"从哪来"（`source_project` / `source_path` / `ext_json.sourceUrl`）。
3. **不猜**：抓不到、读不了、页面是空壳 → 记录失败原因并停下问用户，不用旧缓存冒充。
4. **不绕限制**：不抓登录、付费墙、验证码页面；不批量爬站；每次少量、必要时限速。

## 1. `local-repo`（外部项目代码）

**用途**：从其他仓库/工作空间萃取组件、方案、可复用实现。

**输入**：项目路径（纯英文路径；WSL 下即 `/mnt/...`）、可选代码范围（类/包/目录）、可选 GitNexus 索引。

**工具矩阵**：

| 任务 | DSH 工具 |
|---|---|
| 目录/文件清单 | 文件工具（glob/read）、`bash` + `find`/`ls` |
| 代码检索 | `grep` / `rg`；`bash` + `grep -rn` |
| 依赖/构建信息 | 读 `pom.xml`、`build.gradle`、`package.json` 等 |
| Git 上下文 | `git -C <path> log/rev-parse/remote`（只读） |
| 索引增强 | 有 GitNexus MCP 时用 `impact`/`query`/`context`；没有则 grep/read |

**产出**：文件清单、类/包关系、外部依赖、业务耦合点、敏感字段候选、可复用性初判。

**降级**：无 GitNexus → 纯 grep/read（**不阻断**）；路径含中文/空格 → 加引号或改用文件工具；超大仓库 → 先按范围收敛，不做全仓扫描。

## 2. `workspace-doc`（任意工作空间的文档）

**用途**：从外部项目的 README/设计文档/规范/方案里萃取可复用知识。

**输入**：目录或文件列表（md / txt / rst / sql 等文本），可限定主题。

**工具矩阵**：文件工具、`grep`、`bash`（只读）。

**产出**：文档结构、关键结论、可复用方案（问题→步骤→验证）、规范条目。

**降级**：二进制/Office 文档 → 用 office skill 或 PDF 阅读器按需读取；读不了就记录并询问用户是否换格式。

## 3. `web-page`（网站 / 在线文档）

**用途**：把学到的编程技巧、项目管理方法、工具用法**总结归纳**成魔典笔记（不是全文搬运）。

**输入**：一个或多个 URL（用户给出），可附"重点看什么"。

**工具矩阵**：

| 任务 | DSH 工具 |
|---|---|
| 普通页面原文 | `web_fetch` |
| JS 渲染/需要摘要 | `read_page`（支持聚焦问题） |
| 页面里的图片/图表 | `modlens_read_image` / `read_image`（按需） |
| PDF 链接 | 发现并选择 PDF 阅读器（如 `ops_read_pdf`） |
| 兜底 | `bash` + `curl`（仅在 web 工具不可用时；注意编码与 TOS） |

**采集内容**（默认）：
- 标题、站点/作者、URL、抓取时间、许可/版权声明（若页面有）；
- **总结归纳**：核心结论、关键步骤/要点、适用场景、限制与坑；
- 必要的短引用（标明出处），不整段复制受版权保护正文。

**禁止**：登录/付费墙/验证码页面；批量爬站；把页面里的 token/内网地址/个人信息带入。

**失败**：页面空壳、403、超时 → 记录失败原因并停下问用户（换 URL 或由用户粘贴正文）。

## 4. `pasted-text`（用户粘贴）

**输入**：用户直接粘贴的正文/片段，附来源与用途说明。

**产出**：按分类规则处理（NOTE 摘要 / CODE 片段 / SOLUTION 步骤）。

**要求**：用户需声明来源/许可；无法确认来源时只做"内部笔记"，并在报告中标注"来源不明"。

## 5. 失败与降级总表

| 情况 | 行为 |
|---|---|
| 源路径不存在/无权限 | 报错停止，列出期望路径 |
| 源是二进制/无法解析 | 尝试专用阅读器；失败则询问用户 |
| 网页需登录/付费 | 不绕过；请用户提供正文或换源 |
| 网页内容为空壳 | 用 `read_page` 重试一次；仍失败则停 |
| 源项目过大 | 先按用户范围收敛；不做全仓扫描 |
| 源文件含疑似凭据 | 立即停止并报告，不落盘 |

## 6. 与落盘的关系

源适配器只负责"读进来 + 记录来源"；分类、脱敏、路由、入库分别由：
`SKILL.md` 的 `ingest` 流程 → `references/desensitization-patterns.md` → `references/knowledge-landing.md` 完成。
