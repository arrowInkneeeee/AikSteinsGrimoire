# 部署方式决策矩阵

## 决策矩阵

| 环境条件 | 推荐部署方式 | 说明 |
|---------|------------|------|
| 传统服务器 + 熟悉 Linux | **Systemd** | 标准服务管理，稳定可靠 |
| 已有 Docker 环境 | **Docker** | 容器化部署，环境一致 |
| 本地开发测试 | **Docker Compose** | 一键启动多服务依赖 |
| 多服务依赖 | **Docker Compose** | 编排多个容器 |

## 评估因素

- 是否有 Docker 环境？
- 运维团队熟悉度
- 是否需要快速扩缩容
- 是否有 K8s 平台

## 配置中心选择

```
检查 pom.xml：
- 存在 nacos 依赖 → 提供 Nacos 配置方案
- 不存在 → 使用外置配置文件

混合方案：
- 非敏感配置 → Nacos
- 敏感配置 → 外置文件 + 环境变量
```

## 监控深度选择

| 需求级别 | 方案 | 说明 |
|---------|------|------|
| 基础需求 | Actuator + 日志 | 默认方案，轻量级 |
| 中等需求 | + 健康检查告警 | 增加监控告警 |
| 高级需求 | + Prometheus | 需要时询问用户 |

## 部署检查清单

### 部署前

- [ ] 代码已合并到发布分支
- [ ] 版本号已更新
- [ ] 数据库脚本已准备（如需要）
- [ ] 配置文件已审核
- [ ] 备份策略已确认

### 部署中

- [ ] 旧版本已备份
- [ ] 部署包已上传
- [ ] 配置文件已更新
- [ ] 应用启动成功
- [ ] 健康检查通过

### 部署后

- [ ] 功能验证通过
- [ ] 日志无异常
- [ ] 监控数据正常
- [ ] 通知相关人员

## 回滚策略

- 保留最近 5 个版本备份
- 快速回滚时间 < 5 分钟
- 回滚步骤：停止新版本 → 恢复旧版本 → 启动验证
