# 交接 SKILL（便携单文件版）

把当前对话中的临时上下文、工作状态和散落资产转换为可携带、可核验、可恢复的 `handoff_bundle/`，让另一个 GPT、Codex 任务或 AI Agent 能在不重新猜测背景的情况下继续工作。

本文件是可直接上传给其他 GPT 学习的单文件版本。它已内嵌工作流、模板、资产格式、安全规则和接收协议，不依赖外部参考文档。

## 使用原则

1. 事实优先于聊天叙事。工作区、实际文件、Git 状态和验证结果与聊天记忆冲突时，以可验证事实为准，并记录冲突。
2. 只收集本次任务明确上传、引用、读取、修改或生成的资产。禁止通过扫描整个临时目录、用户目录、下载目录或浏览器资料目录猜测资产。
3. 不得打包密码、API 密钥、Cookie、会话令牌、私钥、凭据文件或无关个人文件。
4. 不得声称不存在的能力。如果当前 GPT 没有文件系统、命令执行、哈希或创建新任务权限，必须说明未执行的部分，并输出可供用户手动保存的内容。
5. 只有全部必需资产存在且校验通过，才能宣布交接包完整。
6. 默认只生成交接包。只有用户明确要求创建、打开或转移到新任务时，才允许新建任务并发送交接。

## 能力模式

开始前判断当前环境：

- **完整模式**：可读写本地文件、复制附件、运行 Git、计算 SHA-256，并能使用任务管理工具。执行完整流程。
- **文件模式**：可读写文件和计算哈希，但不能新建任务。生成并验证交接包，把路径和启动提示词交给用户。
- **对话模式**：不能访问本地文件系统。仅生成 `HANDOFF.md`、资产候选清单和启动提示词的文本内容；要求用户重新上传必需资产。不得声称已经复制文件、读取 Git 或验证哈希。

## 多模态能力与降级

除上述环境能力外，开始前还必须判断当前模型是否支持图片、视频、音频的读取与理解：

- **多模态可用**：模型可直接处理图片、视频、音频。正常收集、复制和描述这些资产。
- **多模态不可用**：模型不支持非文本资产。执行以下降级策略：
  1. 不尝试读取、分析或内联引用图片/视频/音频内容。
  2. 若对话或工作区中存在此类资产，通过文件名、扩展名、用户提供的描述或路径来识别其存在，并在资产候选表中记录；`category` 仍按原类型标注（`images`/`references`），`status` 设为 `unavailable`，`purpose` 中注明"当前模型不具备多模态能力，无法内联处理该资产"。
  3. 在 `HANDOFF.md` 的"资产要求"中明确列出这些资产，并提示"需接收方环境支持多模态，或由用户手动补充"。
  4. 这些资产不参与 SHA-256 校验（因当前模型无法读取内容），但必须在 `ASSET_MANIFEST.json` 中保留记录以提醒接收方。
  5. 多模态资产标记为 `unavailable` 时，不阻断交接包生成，但必须在 `warnings` 和最终回复中明确告知用户。

## 固定输出结构

```text
handoff_bundle/
├── HANDOFF.md
├── ASSET_MANIFEST.json
├── NEXT_TASK_PROMPT.md
├── git-status.txt
├── changes.patch
├── checksums.sha256
├── assets/
│   ├── images/
│   ├── documents/
│   └── references/
└── README.md
```

分类规则：

- 常见图片放入 `assets/images/`。
- PDF、Word、Excel、PPT、Markdown、TXT、CSV、JSON、HTML 等放入 `assets/documents/`。
- 视频、音频、源码、数据目录和其他文件放入 `assets/references/`。
- 分类只影响存放位置；真实用途和媒体类型必须写入清单。

## 创建流程

### 1. 确定交接范围

从完整对话和可用工作区中提取：

- 当前主目标以及“完成”的验收标准；
- 已完成、进行中、未开始和明确推迟的事项；
- 用户后来作出的纠正、否定、偏好与禁止事项；
- 已作出的关键决策、理由和被否决的替代方案；
- 失败尝试、错误结果和不能再重复的踩坑；
- 修改或生成的文件、验证命令和真实结果；
- 阻塞、风险、未决问题和精确的下一步；
- 下一任务可能需要调用的技能或工具。

不要平均压缩所有历史。优先保留会影响继续工作的内容，尤其是用户纠正、未完成状态、精确标识符、文件路径、数值和失败原因。

**多模态降级**：若当前模型不具备多模态能力，遇到图片/视频/音频资产时不要求读取其内容，只需识别其存在和用途（由用户描述或文件名推断），并在后续资产候选表中按降级策略标记。

### 2. 编写 HANDOFF.md

使用以下固定结构。某部分为空时写“无”，不要删除标题。

```markdown
# 任务交接：<标题>

## 一句话状态
<目标、当前完成度、准确的下一动作>

## 原始目标与验收标准
- 目标：
- 完成必须满足：

## 已完成
- <可验证结果；附文件路径或检查命令>

## 当前状态
- 工作区：
- Git 分支/提交：
- 未提交工作：
- 已验证：
- 未验证：

## 用户纠正与固定偏好
- <用户纠正过的事实、明确要求和禁止事项>

## 关键决策
- <决定、理由、被否决的替代方案>

## 踩坑与失败尝试
- <尝试、结果、失败原因；避免接收方重复探索>

## 关键文件和外部引用
- `<path-or-url>`：<作用>

## 资产要求
- 必须交接：<与 ASSET_MANIFEST.json 对应>
- 仅供参考：<与 ASSET_MANIFEST.json 对应>

## 待完成事项
1. <精确的第一步>
2. <后续步骤>

## 风险、阻塞和未决问题
- <明确未知项以及当前倾向>

## 建议技能
- `$<skill-name>`：<何时使用>

## 接收方首次回复要求
在执行任何修改前，复述：目标与验收标准、已完成/待完成、必需资产及校验结果、风险阻塞、准备采取的第一步。
```

已有规格、计划、ADR、Issue、提交、差异文件和成品只引用路径或 URL，不重复粘贴全部内容。任何凭据只能写成“凭据已配置”或“需要用户重新提供”，不能保存其值。

### 3. 建立资产候选表

候选来源仅包括：

- 当前对话明确提供的附件路径；
- 用户点名要求保留的文件；
- 本任务中实际读取、编辑或生成的文件；
- 为继续工作不可缺少的局部代码、数据、图片、视频、音频或文档。

为每项资产记录：

- `path`：原始绝对路径，或相对工作区的路径；
- `purpose`：接收方为什么需要它，不能只写"附件"；
- `priority`：`required` 或 `reference`；
- `category`：`images`、`documents` 或 `references`；
- `destination_name`：如需改名，必须是普通文件名，不能包含目录穿越片段。

**多模态降级**：若当前模型不具备多模态能力，对图片/视频/音频资产不尝试打开或解析，仅记录其元数据（文件名、路径、用户描述）；`priority` 和 `category` 正常标注，后续在 `ASSET_MANIFEST.json` 中标记 `status` 为 `unavailable`，并在 `purpose` 中说明能力限制。

优先级含义：

- `required`：没有它就无法可靠继续或验收任务；缺失时必须阻断交接。
- `reference`：用于佐证、比较、风格参考或回溯；缺失时可以交接，但必须警告。

目录可以作为资产，但只能递归复制正常文件，并排除 `.git`、`.svn`、`.hg`、`node_modules`、虚拟环境和缓存目录。不得跟随符号链接进入未知目录。

### 4. 复制并持久化资产

1. 在工作区或用户指定的持久化目录中创建新的 `handoff_bundle/`。
2. 如果目标已存在，不覆盖；使用带时间戳的新目录，或询问用户如何处理旧包。
3. 将资产复制到相应分类目录，保留原始扩展名。
4. 同名不同内容的文件使用短哈希后缀避免覆盖。
5. 内容完全相同的文件可以去重，但清单中必须保留每个来源与用途。
6. 临时目录中的附件必须复制到包内；清单不能只保留随时可能失效的临时路径。
7. 禁止复制名称明显属于敏感凭据的文件，例如 `.env`、私钥、Cookie、credential、token、password 或 secret 文件。

### 5. 生成 ASSET_MANIFEST.json

格式如下：

```json
{
  "schema_version": "1.0",
  "created_at": "<ISO-8601 时间>",
  "source_workspace": "<源工作区绝对路径或 unavailable>",
  "bundle_path": "<交接包绝对路径或 unavailable>",
  "summary": {
    "total": 0,
    "required": 0,
    "reference": 0,
    "copied": 0,
    "problems": 0
  },
  "assets": [
    {
      "source_path": "<原始路径>",
      "source_root": null,
      "destination_path": "assets/images/example.png",
      "purpose": "<明确用途>",
      "priority": "required",
      "category": "images",
      "media_type": "image/png",
      "size_bytes": 12345,
      "sha256": "<64位十六进制哈希>",
      "status": "copied"
    }
  ],
  "warnings": []
}
```

允许的 `status`：

- `copied`：已复制且可以核验；
- `missing`：源文件不存在；
- `rejected`：被安全规则拒绝；
- `error`：复制或读取失败；
- `unavailable`：当前 GPT 没有文件工具，无法实际处理。

每个实际复制的文件必须记录源路径、相对目标路径、用途、优先级、分类、媒体类型、字节数和 SHA-256。目录输入展开成单文件记录，并保留 `source_root`。

### 6. 捕获 Git 状态

如果工作区是 Git 仓库，在创建交接目录之前捕获：

```text
git status --short --branch --untracked-files=all
git diff --binary --no-ext-diff HEAD --
```

- 第一条输出写入 `git-status.txt`。
- 第二条输出写入 `changes.patch`。
- `changes.patch` 通常只包含已跟踪文件相对 `HEAD` 的修改；未跟踪文件应在状态中列出，并在需要时作为资产单独复制。
- 写入前检查补丁是否包含密码、令牌或密钥；发现疑似敏感值时脱敏并在 `warnings` 说明补丁不再适合直接应用。
- 如果不是 Git 仓库或命令不可用，两个文件仍必须存在，并明确写入“Git 状态/补丁不可用”的原因。

### 7. 生成 checksums.sha256

对交接包内除 `checksums.sha256` 自身之外的每个文件计算 SHA-256，使用以下格式：

```text
<64位小写哈希><两个空格><相对路径，使用正斜杠>
```

例如：

```text
0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef  HANDOFF.md
abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789  assets/images/reference.png
```

校验时必须同时检查：

- 固定文件和三个资产目录全部存在；
- 每个包内文件都被 `checksums.sha256` 覆盖；
- 清单没有重复路径或指向包外的路径；
- 每个实际文件的 SHA-256 与校验表一致；
- 每个 `required` 资产的状态为 `copied`、目标文件存在，并与清单哈希一致。

任何必需资产缺失、拒绝、不可读或哈希不一致都必须使校验失败。

### 8. 生成 NEXT_TASK_PROMPT.md

写入以下内容，并替换交接包路径：

```text
请使用“交接 SKILL”的接收模式。已验证的交接包位于：<交接包绝对路径>。

在做任何修改之前：
1. 按 README.md 中的说明验证整个交接包。
2. 完整读取 HANDOFF.md、ASSET_MANIFEST.json、git-status.txt 和 README.md。
3. 首次回复先复述：目标和验收标准；已完成与待完成；每个 required 资产及其校验状态；缺失项、阻塞和风险；准备执行的准确第一步。
4. 若任一 required 资产缺失、被拒绝、不可读或哈希不匹配，立即停止并报告，不得猜测继续。
5. 复述确认无误后，从 HANDOFF.md 的第一个待办继续，并遵守其中全部用户纠正和约束。
```

若接收方无法访问原电脑的绝对路径，用户必须上传整个交接包，或通过共享存储传输。不能把原电脑路径当作跨电脑传输本身。

### 9. 生成 README.md

至少说明：

- 创建时间和源工作区；
- 每个固定文件的用途；
- 资产总数、必需/参考数量、复制成功与异常数量；
- 当前环境实际使用的校验命令或校验方法；
- `changes.patch` 对未跟踪文件的限制；
- 自动敏感文件检测只是防线，不能替代人工审核；
- 必需资产或校验失败时不得继续任务。

## 验证流程

生成后完整阅读 `HANDOFF.md`、`ASSET_MANIFEST.json` 和 `README.md`，检查用途、分类、路径和警告是否真实。

如果能执行命令：

- Windows PowerShell 可使用 `Get-FileHash -Algorithm SHA256`。
- Linux/macOS 可使用 `sha256sum` 或 `shasum -a 256`。
- 也可以用可信的标准库逐文件计算 SHA-256。

校验失败时：

1. 不得宣布完成；
2. 列出具体失败文件和原因；
3. 补齐或移除错误资产后重新生成校验表；
4. 重新验证整个包，而不是只验证刚修复的文件。

## 创建新任务与发送

只有用户明确要求创建新任务时执行：

1. 先完成并验证交接包。
2. 完整读取 `NEXT_TASK_PROMPT.md` 和 `HANDOFF.md`。
3. 识别当前工作区对应项目。不得擅自选择无关项目。
4. 如果需要新工作树继承当前未提交修改，使用宿主明确支持的 working-tree 起点；否则不要假设新任务能看到这些修改。
5. 新任务的初始消息必须内联：
   - `NEXT_TASK_PROMPT.md` 的要求；
   - `HANDOFF.md` 全文；
   - `ASSET_MANIFEST.json` 的摘要；
   - 交接包绝对路径或用户上传说明。
6. 等待接收方第一次有效回复。
7. 接收方必须复述目标、状态、所有必需资产、校验结果、风险和第一步。
8. 若复述遗漏或错误，发送纠正并再次要求确认。确认正确后才算交接完成。

如果宿主没有创建新任务或跨任务发消息工具，不能模拟成功；把启动提示词交给用户手动粘贴。

## 接收模式

收到交接包时：

1. 先验证固定目录、校验表和所有必需资产。
2. 完整读取 `HANDOFF.md`、`ASSET_MANIFEST.json`、`git-status.txt` 和 `README.md`。
3. 在修改任何文件之前，先复述：
   - 最终目标和验收标准；
   - 已完成、进行中和待完成事项；
   - 每个 `required` 资产及其校验状态；
   - 缺失资产、阻塞、风险和未决问题；
   - 准备执行的准确第一步。
4. 如果必需资产缺失、哈希不匹配、路径不可读，或工作区状态与交接文档明显冲突，停止并报告。
5. 只有校验通过且复述完成后，才从第一个待办继续。

## 完成标准

- 固定输出全部存在；
- `checksums.sha256` 覆盖所有包内文件并校验通过；
- 每个资产都有来源、相对目标、用途、优先级、字节数和 SHA-256；
- 所有必需资产均已复制，缺失项没有被静默忽略；
- Git 状态和补丁明确说明是否来自有效 Git 工作区；
- `NEXT_TASK_PROMPT.md` 强制执行“先核验、再复述、后继续”；
- 敏感信息和无关文件未进入交接包；
- 最终回复给出交接包路径、资产数量、必需/参考分类、校验结果，以及是否创建了新任务；
- 如果环境能力不足（包括非多模态模型无法处理图片/视频/音频），最终回复必须精确区分"已生成""仅提供文本""尚未复制""尚未验证"和"尚未发送"，并明确说明哪些资产因模型能力限制未被处理。

## 给其他电脑 GPT 的安装或学习方法

### 作为 Codex/Agent Skill 安装

将本文件重命名为 `SKILL.md`，保存到：

```text
~/.codex/skills/codex-handoff-bundle/SKILL.md
```

重新启动或刷新技能列表后，使用：

```text
使用 $codex-handoff-bundle，把当前任务和相关资产制作成可验证交接包。
```

### 作为普通 GPT 知识文件使用

直接上传本 Markdown，并发送：

```text
请完整学习这份“交接 SKILL”。以后当我要求交接任务、保存上下文、转移到新对话或打包附件时，严格按文件中的流程执行；没有文件或任务工具时必须明确说明能力限制，不得假装已复制、校验或发送。
```

### 推荐调用语句

```text
使用交接 SKILL，把当前任务、用户纠正、未完成事项和所有相关资产制作成完整交接包。
```
