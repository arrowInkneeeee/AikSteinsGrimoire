# HANDOFF.md 模板与字段规范

## 字段填写规范

| 字段 | 写什么 | 不写什么 |
|------|--------|---------|
| 一句话状态 | 目标 + 当前完成度 + 准确的下一动作（三要素缺一不可） | 模糊的"进行中""快好了" |
| 原始目标与验收标准 | 目标、完成必须满足的可验证条件 | 重新展开需求文档全文 |
| 已完成 | 可验证结果；附文件路径或检查命令 | 主观描述"基本完成" |
| 当前状态 | 工作区、Git 分支/提交、未提交工作、已验证/未验证项 | 省略未验证项 |
| 用户纠正与固定偏好 | 会影响继续工作的纠正、明确要求和禁止事项 | 寒暄、一次性闲聊 |
| 关键决策 | 决定、理由、被否决的替代方案 | 只写决定不写理由 |
| 踩坑与失败尝试 | 尝试 → 结果 → 失败原因（三段式） | 只写"试过不行" |
| 关键文件 | 路径或 URL + 作用 | 粘贴全文内容 |
| 资产要求 | 与 ASSET_MANIFEST.json 对应的必需/参考资产 | 重复清单全部字段 |
| 待完成事项 | 精确的第一步 + 后续步骤 | 概括性"继续开发" |
| 风险阻塞 | 明确未知项 + 当前倾向 | 只列风险不给倾向 |
| 建议技能 | `$skill-name`：何时使用（aik 生态内）；外部 GPT 留空或写通用描述 |  |
| 接收方首次回复要求 | 固定复述清单（见下方） |  |

**凭据红线**：任何字段中，凭据只能写成"凭据已配置"或"需要用户重新提供"，不能保存其值。

## 骨架（复制此段后填写）

```markdown
# 任务交接：<标题>

## 一句话状态
<目标、当前完成度、准确的下一动作>

## 原始目标与验收标准
- 目标：
- 完成必须满足：

## 已完成
- <可验证结果；附文件路径或检查命令>

## 当前状态
- 工作区：
- Git 分支/提交：
- 未提交工作：
- 已验证：
- 未验证：

## 用户纠正与固定偏好
- <用户纠正过的事实、明确要求和禁止事项>

## 关键决策
- <决定、理由、被否决的替代方案>

## 踩坑与失败尝试
- <尝试、结果、失败原因；避免接收方重复探索>

## 关键文件和外部引用
- `<path-or-url>`：<作用>

## 资产要求
- 必须交接：<与 ASSET_MANIFEST.json 对应>
- 仅供参考：<与 ASSET_MANIFEST.json 对应>

## 待完成事项
1. <精确的第一步>
2. <后续步骤>

## 风险、阻塞和未决问题
- <明确未知项以及当前倾向>

## 建议技能
- `$<skill-name>`：<何时使用>

## 接收方首次回复要求
在执行任何修改前，复述：目标与验收标准、已完成/待完成、必需资产及校验结果、风险阻塞、准备采取的第一步。
```

## 建议技能字段的双模式

| 接收方环境 | 写法 | 示例 |
|-----------|------|------|
| aik 生态内（装了 aik-skills-lab） | `$skill-name`：何时使用 | `$spec-implementer`：从 SDD 继续生成代码骨架 |
| 外部 GPT（未装 aik-skills-lab） | 留空，或写通用动词描述 | "需要继续生成后端代码骨架" |

这保证交接包在 aik 生态内有技能联动增益，在生态外不产生无法解析的引用。
