# spec-component-extractor

## 职责

1. 接收用户指定的代码范围（文件/包/类/方法）
2. 自动检查/构建 gitnexus 索引
3. 协调各原子技能执行萃取流程
4. 产出 10 章结构化 Component Manual

## 执行流程

```
用户指定范围 + 粒度
    │
    ▼
步骤0: 自动索引检查 — 调用 gitnexus 技能
    ├── npx gitnexus status → 检查索引是否存在且新鲜
    ├── 如不存在或过期 → npx gitnexus analyze → 等待完成
    └── 确认索引就绪后进入步骤1
    │
    ▼
【人工卡点1：范围确认】
    回显：用户指定的文件/包/方法列表
    确认：粒度级别（技术方案级 / 组件级）
    确认：组件用途描述
    询问用户是否补充遗漏
    │
    ▼
步骤1: gitnexus 语义探索
    ├── gitnexus query → 按业务概念搜索相关流程
    ├── gitnexus context → 核心符号 360° 视图
    └── gitnexus cypher → 追踪完整调用链
    │
    ▼
步骤2: component-code-analyzer → 6 维度代码分析报告
    │
    ▼
【人工卡点2：分析报告审核】
    展示：架构模式、耦合清单、敏感数据、依赖关系
    询问：是否补充遗漏的耦合点？是否有误判？
    │
    ▼
步骤3: process-designer → 核心流程时序图
    │
    ▼
步骤4: architecture-designer → 组件分层映射 + 包结构规范化
    │
    ▼
步骤5: tech-solution-selector → 技术依赖分析 + 中间件方案
    │
    ▼
步骤6: doc-writing-helper → 整合为 10 章 Component Manual
    │
    ▼
步骤7: design-review-checker → 手册完整性与清晰度审核
    │
    ▼
【人工卡点3：组件手册最终审批】
    展示：手册关键指标（耦合点数量、敏感数据数量、类清单）
    选项：A) 批准保存  B) 修订内容  C) 仅保存暂不复写
    │
    ▼
产出：Component Manual v1.0
```

## 调用的技能

| 顺序 | 技能名称 | 用途 |
|------|---------|------|
| 0 | gitnexus | 自动检查/构建索引（CLI），语义探索(query+context+cypher) |
| 1 | component-code-analyzer | 6维度代码分析（架构/分层/耦合/敏感/依赖/扩展点） |
| 2 | process-designer | 核心流程时序图绘制 |
| 3 | architecture-designer | 组件分层映射、包结构规范化 |
| 4 | tech-solution-selector | 依赖分析、技术中间件方案梳理 |
| 5 | doc-writing-helper | 正式风格文档撰写，整合为结构化手册 |
| 6 | design-review-checker | 手册完整性审核 |

## 步骤0：自动索引检查

```
// 检查索引状态
npx gitnexus status

// 情况A：索引存在且新鲜 → 跳过
// 情况B：索引不存在 → 自动构建
npx gitnexus analyze
// 情况C：索引过期 → 自动刷新
npx gitnexus analyze

// 验证
npx gitnexus status  → 确认 "Status: ✅ up-to-date"
```

> 此步骤对用户透明。仅在构建失败或项目路径含中文时报错提示。

## 两种粒度的差异处理

| 方面 | 技术方案级 | 组件级 |
|------|-----------|--------|
| 萃取范围 | 多个关联类、配置、中间件 | 单个类或少量紧密关联的类 |
| 手册侧重点 | 方案全局架构、技术选型理由、组件协作关系 | 核心算法、接口设计、参数说明 |
| 流程设计 | 多组件交互时序图 | 单组件内部流程 |
| 脱敏指导 | 跨组件依赖抽象化 | 单组件参数化 |

## 文档模板

Component Manual 10 章结构：
```
# 组件手册：{组件名称}
## 1. 组件概述（功能描述/技术特征/适用场景）
## 2. 架构设计（包结构/分层映射/设计模式）
## 3. 类与接口清单（核心类/扩展点）
## 4. 核心流程（时序图/事务边界/异步处理）
## 5. 配置与依赖（外部Maven依赖/内部依赖/配置属性）
## 6. 业务耦合清单（耦合ID/位置/类型/脱敏建议）
## 7. 敏感数据清单（敏感ID/位置/类型/处理方式）
## 8. 脱敏与复写指导（命名映射表/抽象化策略/配置外化清单）
## 9. 使用指南（快速开始/配置说明/扩展示例）
## 10. 附录（源文件清单/依赖树/变更历史）
```

## 强制规范

- 步骤0 必须执行，索引就绪才能继续
- 3 个人工卡点必须暂停等待用户确认，不允许跳过
- 耦合清单必须精确到方法级别，脱敏建议必须具体可操作
- 敏感数据检测零容忍，全部标注
- 手册产出前必须通过 design-review-checker 审核
