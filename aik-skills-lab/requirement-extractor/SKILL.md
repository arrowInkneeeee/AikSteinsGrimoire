# requirement-extractor

## 输入

- **原始文本**: 会议记录、聊天记录、口头描述等非结构化文本
- **上下文信息**（可选）: 项目背景、业务领域等

## 输出

结构化功能点列表（JSON 格式）

```json
{
  "features": [
    {
      "id": "F001",
      "description": "功能描述",
      "category": "core|auxiliary|technical",
      "source": "原始文本片段"
    }
  ]
}
```

## 工作流

1. **接收原始文本输入**
   - 支持多种格式：纯文本、Markdown、对话记录等

2. **识别并提取功能描述语句**
   - 识别功能关键词（"需要"、"应该"、"必须"、"支持"、"实现"等）
   - 提取完整的功能描述句
   - 保留原始上下文

3. **分类功能类型**
   - **core**: 核心功能，直接服务于主要业务目标
   - **auxiliary**: 辅助功能，提升用户体验
   - **technical**: 技术需求，非功能性需求

4. **去除重复和冗余信息**
   - 检测语义相似的功能描述
   - 合并重复项，保留最完整的描述

5. **输出标准化功能点列表**
   - 分配唯一 ID（F001, F002...）
   - 按类别分组
   - 保留原始来源便于追溯

## 调用规则

- 当接收到非结构化的需求描述时自动调用
- 可与其他技能链式调用
- 输出直接传递给 requirement-clarifier 进行下一步处理

## 示例

### 输入

```text
产品经理：我们需要做一个电商 APP，用户可以快速浏览商品，支持购物车功能。
开发：需要接入支付接口吗？
产品经理：是的，要支持微信支付和支付宝。还要有个后台管理系统让运营人员上架商品。
```

## 注意事项

- 保留所有原始表述，即使看似重复
- 对于模糊描述，先提取后标记，由 clarifier 处理
- 技术实现细节（如"用 Redis 缓存"）归类为 technical
