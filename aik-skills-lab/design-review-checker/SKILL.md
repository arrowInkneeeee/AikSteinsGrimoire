# design-review-checker

## 输入

- **完整设计文档**: 架构设计 + 数据库设计 + API 设计 + 流程设计 + 技术选型

## 输出

设计评审报告

## 工作流

1. **项目复用检查**
   - 检查是否复用项目已有组件
   - 检查是否符合项目现有规范

2. **分层规范检查**
   - Controller/Service/Mapper 职责
   - Entity/DO/DTO/VO 分离
   - Service 接口与实现

3. **数据库设计检查**
   - 命名规范
   - 索引设计
   - 三范式

4. **接口设计检查**
   - RESTful 规范
   - 幂等性
   - 安全性

5. **性能风险检查**
   - N+1 查询
   - 深度分页
   - 大事务

6. **Java 代码规范检查**
   - Stream API
   - Optional
   - 日志规范

7. **生成分类评审报告**

## 检查清单

### 项目复用检查

- [ ] Result、PageResult 是否复用项目已有
- [ ] BaseEntity 是否复用项目已有
- [ ] 工具类是否复用项目已有（不重复创建 DateUtil、JsonUtil 等）
- [ ] 常量类是否复用项目已有（CacheKey、ResultCode 等）
- [ ] 配置类是否复用项目已有（RedisConfig、MybatisPlusConfig 等）
- [ ] 异常类是否复用项目已有（BusinessException 等）
- [ ] 技术选型是否匹配项目已有依赖（pom.xml）

### 分层规范检查

- [ ] Controller 只负责参数校验和调用 Service，禁止业务逻辑
- [ ] Service 必须定义接口，实现放在 impl 包
- [ ] Service 实现是否继承 `ServiceImpl<XxxMapper, XxxEntity>` 和 `IService<XxxEntity>`
- [ ] Mapper 是否继承 `BaseMapper<XxxEntity>`
- [ ] Entity 是否带 `@TableName` 注解（与 DO 区分）
- [ ] DTO/VO/Entity/DO 是否分离，职责清晰
- [ ] Converter 是否定义（实施时决定 MapStruct 或手动）

### 数据库设计检查

- [ ] 表名使用大写下划线（如 `T_ORDER`）
- [ ] 主键使用 `ID`，`BIGINT` 类型
- [ ] 字段使用大写下划线（如 `CREATE_TIME`）
- [ ] 是否包含逻辑删除字段（`DELETED`）
- [ ] 是否包含审计字段（`CREATE_TIME`, `UPDATE_TIME`, `CREATE_BY`, `UPDATE_BY`）
- [ ] 索引命名是否符合规范（`IDX_XXX`, `UK_XXX`）
- [ ] 外键字段是否加索引
- [ ] 是否存在 N+1 查询风险（关联表设计）
- [ ] 大字段是否考虑分表（TEXT, BLOB）
- [ ] 金额是否使用 DECIMAL（禁止 FLOAT/DOUBLE）

### 接口设计检查

- [ ] URL 是否符合 RESTful 规范（名词复数）
- [ ] 是否使用统一返回结果（Result<T>）- **必须复用项目已有**
- [ ] 分页是否使用 PageDTO/PageResult - **必须复用项目已有**
- [ ] 是否考虑接口幂等性（POST/PUT 操作）
- [ ] 敏感操作是否有权限校验
- [ ] 参数校验是否使用 JSR-303 注解
- [ ] 错误码是否统一定义

### 流程设计检查

- [ ] 时序图是否清晰标注参与者
- [ ] 事务边界是否明确
- [ ] 状态机是否定义流转规则
- [ ] 异步操作是否考虑事务提交后再执行
- [ ] 是否存在事务失效场景（同类方法调用等）

### 性能风险检查

- [ ] 是否存在深度分页风险（limit 100000, 10）
- [ ] 循环中是否存在数据库查询（N+1）
- [ ] 大事务是否拆分
- [ ] 是否需要缓存，缓存策略是否合理
- [ ] 慢 SQL 是否优化（EXPLAIN 分析）
- [ ] 是否存在热点数据竞争
- [ ] 外部 API 调用是否考虑超时、重试、降级

### 技术选型检查

- [ ] 缓存方案是否匹配项目已有技术栈
- [ ] 消息队列是否匹配项目已有技术栈
- [ ] 分布式锁是否匹配项目已有技术栈
- [ ] 是否引入不必要的中间件

### Java 代码规范检查

- [ ] 是否使用 Java 8 Stream API/Lambda（集合操作）
- [ ] 空值是否使用 Optional 处理（避免 != null 判断）
- [ ] 日志是否使用 `@Slf4j`（禁止 System.out.println）
- [ ] 异常是否使用自定义 BusinessException - **复用项目已有**
- [ ] 公共方法是否有 Javadoc
- [ ] 变量命名是否 camelCase
- [ ] 常量命名是否大写下划线
- [ ] 是否使用 Lombok（@Data, @Builder, @RequiredArgsConstructor）

## 严重级别定义

| 级别 | 说明 | 处理要求 |
|------|------|---------|
| **P0 - 阻塞** | 设计存在严重缺陷，必须修复 | 阻塞后续开发 |
| **P1 - 严重** | 设计存在风险，建议修复 | 必须记录并跟踪 |
| **P2 - 警告** | 设计可优化，可选修复 | 建议记录 |
| **P3 - 提示** | 设计建议，仅供参考 | 可选处理 |

## 常见设计缺陷

### P0 - 阻塞

| 缺陷 | 说明 | 修复建议 |
|------|------|---------|
| 未复用项目 Result | 创建新的返回格式 | 删除，复用项目已有 Result |
| 数据库无逻辑删除 | 缺少 deleted 字段 | 添加逻辑删除字段 |
| 金额使用 FLOAT | 精度丢失风险 | 改为 DECIMAL |
| 接口无幂等设计 | 重复提交风险 | 添加幂等机制（Token/唯一索引）|

### P1 - 严重

| 缺陷 | 说明 | 修复建议 |
|------|------|---------|
| N+1 查询 | 循环中查询数据库 | 使用 JOIN 或批量查询 |
| 深度分页 | limit 100000, 10 | 限制最大页码或使用游标分页 |
| 大事务 | 事务范围过大 | 缩小事务范围，异步处理 |
| 无索引设计 | 关键字段无索引 | 添加索引 |

### P2 - 警告

| 缺陷 | 说明 | 修复建议 |
|------|------|---------|
| 表名不规范 | 未使用 T_ 前缀 | 统一表名规范 |
| 缺少审计字段 | 无 create_time 等 | 添加审计字段 |
| 索引过多 | 影响写入性能 | 评估索引必要性 |

### P3 - 提示

| 缺陷 | 说明 | 修复建议 |
|------|------|---------|
| 可使用 Stream | 循环可使用 Stream 简化 | 根据可读性决定 |
| 缺少 Javadoc | 公共方法无注释 | 添加注释 |

## 注意事项

- 优先检查项目复用，避免重复造轮子
- 数据库设计要符合三范式，适当反范式设计
- 性能问题要给出具体的优化建议
- 事务边界要明确，避免大事务和事务失效
- 检查清单可根据项目实际情况调整
