# code-review

代码审查全流程技能，覆盖风格、质量、安全和缺陷模式四个维度，确保代码符合规范且无明显缺陷。

## 子命令

### style

代码风格审查——检查命名、注释、格式是否符合 aIk-coding-style 规范。

**触发条件**：用户说"风格审查"、"检查命名"、"检查注释"

**输入**：
- Java源代码文件

**输出**：
- 风格审查报告（问题列表 + 修复建议）

**执行步骤**：
1. 加载 `references/style-guide.md` 审查清单
2. 加载 `assets/style-checklist.md` 检查模板
3. 逐项检查：
   - **命名规范**：类名驼峰、方法名驼峰、常量全大写下划线、PO用XxPo/DTO用XxDto/VO用XxVo
   - **类注释**：是否使用 `-anchor` 模板，`@author a I k .`
   - **代码注释**：是否使用 `//note` 和 `//anchor` 标记，禁止行尾注释
   - **依赖注入**：是否使用 `private final` + `@RequiredArgsConstructor`
   - **Service Bean名称**：是否使用 `{module}.{ServiceName}` 格式
   - **PO注解**：无继承用 @Builder，有继承用 @SuperBuilder
   - **VO方法**：是否包含 `of()` 转换方法
   - **XML位置**：是否在 Java源码目录的 `dao/mapping/` 下
   - **格式**：if必须使用大括号，缩进统一
4. 输出风格审查报告

### quality

代码质量审查——检查N+1查询、空指针风险、事务边界等质量问题。

**触发条件**：用户说"质量审查"、"检查N+1"、"检查事务"

**输入**：
- Java源代码文件

**输出**：
- 质量审查报告（问题列表 + 严重度 + 修复建议）

**执行步骤**：
1. 加载 `references/quality-guide.md` 审查指南
2. 加载 `assets/quality-report-template.md` 报告模板
3. 逐项检查：
   - **N+1查询**：循环内是否有数据库调用，是否应改为批量查询或JOIN
   - **空指针风险**：未做null检查的链式调用、Optional使用不当
   - **事务边界**：@Transactional是否标注正确，传播行为是否合理
   - **异常处理**：是否有空catch、是否吞掉异常、异常类型是否精确
   - **并发安全**：共享可变状态、非线程安全集合的并发使用
   - **资源泄漏**：IO/数据库连接是否正确关闭（try-with-resources）
   - **分页限制**：是否限制最大页码和每页数量
4. 为每个问题标注严重度（P0-P3）
5. 输出质量审查报告

### security

代码安全审查——检查SQL注入、越权访问等安全漏洞。

**触发条件**：用户说"安全审查"、"检查SQL注入"、"检查越权"

**输入**：
- Java源代码文件

**输出**：
- 安全审查报告（漏洞列表 + 风险等级 + 修复方案）

**执行步骤**：
1. 加载 `assets/security-report-template.md` 报告模板
2. 逐项检查：
   - **SQL注入**：MyBatis中是否使用 `${}` 拼接用户输入，应改为 `#{}`
   - **越权访问**：是否校验资源归属（如订单查询是否校验当前用户）
   - **敏感数据泄露**：日志中是否打印密码、token等敏感信息
   - **输入校验**：Controller层是否做参数校验（@Valid, @NotNull等）
   - **权限控制**：接口是否有权限注解（@PreAuthorize等）
   - **XSS**：返回用户输入时是否做转义
   - **CSRF**：状态变更接口是否有防护
3. 为每个漏洞标注风险等级（高/中/低）
4. 输出安全审查报告

### bug-pattern

缺陷模式分析——识别代码中的常见缺陷模式，提供预防建议。

**触发条件**：用户说"缺陷分析"、"分析缺陷模式"、"预防缺陷"

**输入**：
- Java源代码文件
- 代码审查结果（可选）
- 测试结果（可选）

**输出**：
- 缺陷模式分析报告（模式识别 + 根因分析 + 预防建议）

**执行步骤**：
1. 加载 `references/bug-patterns.md` 中的8种缺陷模式
2. 扫描代码，匹配以下缺陷模式：
   - **空指针异常（NPE）**：未检查的返回值、链式调用
   - **并发缺陷**：竞态条件、死锁风险
   - **资源泄漏**：未关闭的流、连接
   - **SQL注入**：动态SQL拼接
   - **事务问题**：自调用失效、异常被捕获导致回滚失败
   - **N+1查询**：循环内数据库调用
   - **日期时间错误**：时区处理、旧API使用
   - **类型转换**：未检查的强制类型转换
3. 为每个识别的模式分析根因
4. 提供预防建议和代码改进方案
5. 输出缺陷模式分析报告

### full

三维全面审查（风格 + 质量 + 安全 + 缺陷模式）。

**触发条件**：用户说"全面审查"、"代码审查"、"Code Review"

**输入**：
- Java源代码文件（单个文件或目录）

**输出**：
- 综合审查报告（风格 + 质量 + 安全 + 缺陷模式）

**执行步骤**：
1. 执行 `style` → 风格审查
2. 执行 `quality` → 质量审查
3. 执行 `security` → 安全审查
4. 执行 `bug-pattern` → 缺陷模式分析
5. 整合所有结果为综合审查报告
6. 按严重度排序问题列表
7. 输出综合审查报告

| 输出项 | 格式 | 说明 |
|--------|------|------|
| 审查报告 | Markdown表格 | 问题列表 + 严重度 + 文件位置 + 修复建议 |

## 工作流上下文

**上游技能**：
- `code-implementation`：产出待审查的代码

**下游技能**：
- `testing`：审查通过后进行测试
- `devops`：审查+测试通过后进行部署

## 质量门禁

| 检查点 | 条件 | 动作 |
|--------|------|------|
| 风格审查 | 无阻塞性问题 | 继续 |
| 质量审查 | P0=0, P1=0 | 继续，否则修复后重审 |
| 安全审查 | 无高风险漏洞 | 继续，否则修复后重审 |

## 约束

- 风格审查基于 `aIk-coding-style` 规范
- 审查发现的问题应提供具体修复建议（含代码示例）
- 严重度分级：P0=阻塞、P1=严重、P2=警告、P3=建议
