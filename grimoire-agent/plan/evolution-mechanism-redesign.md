# 綾雾彌奈进化机制重构计划

> 版本：v1.0 | 日期：2026-07-31 | 状态：待确认执行
> 基于讨论结论：放弃原 agent-expansion-plan 中的进化协议设计，重构为"对话隔离友好"的四支柱架构

---

## 一、问题诊断（为什么原方案失效）

原方案（`grimoire-agent/agent/evolution-protocol.md`）按"连续服务系统"设计，但 Qoder 的实际运行环境是"无状态离散会话"：

| 失效点 | 表现 | 根因 |
|-------|------|------|
| 信号采集断链 | 每次对话是新实例，无法继承"连续无纠正次数" | 对话隔离 + 无强制写入机制 |
| 计数器脆弱 | LLM 可能忘记读 decision-log / 忘记写 / 算错 | 提示词约束力弱，无运行时强制 |
| 抽象偏好维度 | D1-D6（决策倾向）+ 计划中的 G1-G3 是"推断的推断" | 抽象维度超出 LLM 行为观察能力 |
| 信任阶梯跨对话失效 | Lv.1→Lv.2 需要"连续 5 次无纠正"，跨对话无法统计 | 对话隔离直接否定连续计数前提 |

---

## 二、设计目标

1. **对话隔离友好**：不依赖跨对话持久状态，每个 Quest 内部自洽
2. **可靠性优先**：宁可手动可靠，不追求全自动但脆弱
3. **最小用户成本**：归档触发简单、有兜底提醒、不强求每次操作
4. **可追溯**：所有偏好推断都对应具体决策，不做"推断的推断"

---

## 三、核心架构：四支柱 + 1+1 智能体

### 3.1 四支柱

| 支柱 | 解决的问题 | 实现位置 |
|------|-----------|---------|
| **支柱 1：强制对话结论** | 信号采集断链 | `aIk-agent.md`（硬性规则章节） |
| **支柱 2：用户驱动归档** | 信号无法跨对话持久化 | `aIk-agent.md`（提示词）+ 默认智能体归档 |
| **支柱 3：里程碑制信任进阶** | 计数器脆弱 | `evolution-protocol.md` + `decision-log.md` |
| **支柱 4：具体决策档案** | 抽象偏好维度不可靠 | `decision-log.md`（新格式） |

### 3.2 1+1 智能体架构

**讨论过程中否定的方案**：5 个子智能体（开发搭档/执行者/参谋/朋友 + 归档）
**否决理由**：
- 4 个角色共享 90% 系统提示词，独立化 → 改性格/门禁/编码规范要改 4 次
- 顶层调度器对 LLM 是高认知负荷任务，场景判断易出错
- 角色是"表情"不是"实体"，归档才是真正独立的"工具"

**最终选定：1 主 + 1 归档**

```
┌─────────────────────────────────────────┐
│  aIk-agent（綾雾彌奈）                  │
│  ├─ 内置角色模式切换（开发搭档/执行者/   │
│  │  参谋/朋友），共享核心人格+编码规范   │
│  │  +门禁策略，只切换行为指令            │
│  └─ 每个任务单元结束 → 输出信号摘要     │
└─────────────────────────────────────────┘
                    ↓
      （用户下次开新 Quest，找默认智能体）
      说"记录一下"+ 简单描述
                    ↓
┌─────────────────────────────────────────┐
│  默认智能体（我）                        │
│  ├─ 主路径：执行归档（Read/Write 文件） │
│  ├─ 兜底：检索未归档记忆，主动提醒      │
│  └─ 检查里程碑，提议信任进阶            │
└─────────────────────────────────────────┘
```

## 四、支柱 1：强制对话结论

### 4.1 设计要点

- **触发时机**：每个"任务单元"结束时，而非 Quest 结束时
  - 任务单元定义：完成一个明确的功能/设计/问题解答
  - 不依赖 Quest 是否结束的判断（这个判断 LLM 不可靠）
- **输出位置**：该 Turn 回答的末尾（对话可见，不直接写文件）
- **必须输出**：即使无新信号也要输出"本次无新信号"，避免遗漏

### 4.2 信号摘要模板（写入 `aIk-agent.md`）

```markdown
### 对话结论硬性规则（不可跳过）

每当完成一个明确的任务单元（功能交付/设计稿/问题解答）时，
在回答末尾追加以下信号摘要。无新信号也要输出"本次无新信号"。

---
**📋 本次对话信号摘要**
- 决策记录（如有）：
  - [领域] [具体决策] [结果：被接受/被纠正]
- 纠正信号（如有）：
  - [用户原话] → [推断的偏好]
- 新偏好观察（如有）：
  - [具体行为] → [推断的偏好]
- 无新信号：[是/否]

→ 如需归档到进化日志，下次和我（默认智能体）说"记录一下"
---
```

### 4.3 兜底：UpdateMemory 暂存

在 `aIk-agent.md` 中追加规则：

```markdown
### 信号记忆暂存（兜底机制）

每个任务单元结束时，除了输出信号摘要，还必须调用 UpdateMemory：
- category: task_summary_experience
- title: "未归档信号 - [日期] - [简要主题]"
- content: 信号摘要的完整内容
- keywords: 未归档,信号,[领域关键词]

这是为了让默认智能体下次对话时能检索到并提醒用户归档。
归档完成后，由默认智能体删除该记忆条目。
```

## 五、支柱 2：用户驱动归档

### 5.1 主路径触发方式

**触发时机**：用户下次和默认智能体（我）对话时，主动说"记录一下"

**用户需要做的事**：
1. 开新 Quest（默认智能体）
2. 说"记录一下"+ 简单描述（例如："上次和綾雾做了订单模块，她选了枚举管状态机，这个决策我觉得不错"）

**我（默认智能体）做的事**：
1. 根据描述理解信号内容
2. Read `grimoire-agent/agent/decision-log.md`
3. 追加具体决策记录（带日期）
4. 检查里程碑是否达成（对照 `evolution-protocol.md` 的里程碑表）
5. 如达成里程碑，提议信任进阶
6. 删除对应的"未归档信号"记忆条目

### 5.2 兜底提醒触发方式

**触发时机**：用户和我（默认智能体）对话时，我主动检索未归档信号

**实现机制**：
- 利用 Qoder 的 `<memory_overview>` 机制，未归档信号会以"未归档信号 - ..."标题出现在记忆概览中
- 我每次对话开始时扫一眼记忆概览，发现未归档信号就主动提示：
  "上次有个[主题]的信号还没归档，要现在记吗？"
- 用户确认后走主路径流程

### 5.3 归档操作规范（写入默认智能体的行为约定，此处仅记录，不改文件）

| 步骤 | 动作 | 工具 |
|------|------|------|
| 1 | 读决策档案 | Read `decision-log.md` |
| 2 | 追加新决策（带日期、领域、具体决策、结果） | SearchReplace |
| 3 | 读里程碑跟踪表 | Read `evolution-protocol.md`（里程碑章节） |
| 4 | 对照里程碑判断是否达成 | 纯文本推理 |
| 5 | 如达成，提议信任进阶并更新等级 | SearchReplace `aIk-agent.md` |
| 6 | 删除未归档记忆 | UpdateMemory（delete） |

## 六、支柱 3：里程碑制信任进阶

### 6.1 设计要点

- **放弃"连续 N 次无纠正"**（LLM 数不准）
- **改为可验证的能力里程碑**：写具体行为，不写抽象计数
- **分领域独立跟踪**：后端/前端/通用各自独立进阶
- **各领域起始等级不同**：
  - 后端 Lv.1（用户最熟，要验证的东西多）
  - 前端 Lv.2（用户明确不熟悉，高自主 + 详细决策说明）
  - 通用 Lv.1（默认）

### 6.2 里程碑表结构（写入 `evolution-protocol.md`）

```markdown
### 后端领域里程碑

Lv.1 → Lv.2
- [ ] 独立完成 3 个不同业务模块的 Service 实现
- [ ] 正确使用 MyBatis-Plus 复杂查询 1 次
- [ ] 后端决策未被用户纠正过（累计 3 次决策）
- [ ] 用户主动说"后端你看着办"

Lv.2 → Lv.3
- [ ] 独立完成含事务 + 异常处理 + 日志的完整业务流程
- [ ] 主动识别并规避 1 个潜在性能问题（N+1/慢查询）
- [ ] 用户未对后端决策提出质疑（连续 3 次相关对话）

### 前端领域里程碑（起步 Lv.2）

Lv.2 → Lv.3
- [ ] 独立完成含路由 + 状态 + API 对接的完整页面
- [ ] 正确使用 Vue 3 组合式 API 处理 3 个不同组件
- [ ] 前端决策未被用户纠正过（累计 3 次决策）
- [ ] 用户主动说"前端你看着办"

Lv.3 → Lv.4
- [ ] 独立完成含权限控制 + 状态共享的复杂页面
- [ ] 主动识别并规避 1 个潜在前端问题（性能/可维护性）
- [ ] 用户未对前端决策提出质疑（连续 5 次相关对话）

### 通用领域里程碑

Lv.1 → Lv.2
- [ ] 文件操作/系统操作 5 次无误
- [ ] 参谋类建议被用户接受 3 次
- [ ] 用户主动委托非开发类任务

（通用不进入 Lv.3+，因为通用场景不需要深度授权）
```

### 6.3 信任进阶执行规则

- 里程碑由默认智能体在归档时检查
- 达成后**提议**进阶，不直接改文件，等用户确认
- 用户确认后才更新 `aIk-agent.md` 中的信任等级字段
- 信任可降级：用户明确说"这个我不太放心"时，对应领域回退一级

## 七、支柱 4：具体决策档案

### 7.1 设计要点

- **删除 D1-D6 抽象决策倾向维度**（从未真正生效过，只是装饰）
- **删除计划中的 G1-G3 通用偏好维度**（LLM 提取不可靠）
- **只记录实际发生过的决策**，不做"推断的推断"
- **每条带日期**，可追溯演变
- **按领域分类**：后端/前端/通用

### 7.2 `decision-log.md` 新格式

```markdown
# 决策档案

> 记录实际发生的决策，不做抽象推断。每条带日期，可追溯演变。

## 后端领域

| 日期 | 决策 | 结果 |
|------|------|------|
| 2026-07-30 | 订单状态机用枚举管理，不用状态字段 | confirmed |
| ... | ... | ... |

## 前端领域

| 日期 | 决策 | 结果 |
|------|------|------|
| 2026-07-31 | 新项目 Vue 3 + Element Plus + Pinia | confirmed |
| 2026-07-31 | 前端信任等级起步 Lv.2（用户不熟悉） | confirmed |
| ... | ... | ... |

## 通用领域

| 日期 | 决策 | 结果 |
|------|------|------|
| 2026-07-30 | 交互风格：自然不矫情 | confirmed |
| 2026-07-30 | 命名原则：功能性优先 | confirmed |
| ... | ... | ... |
```

### 7.3 信号采集规则（写入 `evolution-protocol.md`）

```markdown
### 信号采集三原则

1. **只记具体决策，不推断抽象偏好**
   ✓ "订单状态机用枚举管理"
   ✗ "用户倾向于简洁的代码风格"

2. **每条必须对应可观察的行为**
   ✓ "用户说'这个决策不错'"
   ✗ "我推断用户喜欢这种设计"

3. **未经验证的推断标记 [观察]，验证后改为 [确认]**
   - [观察]：单次出现，未被用户明确确认
   - [确认]：用户明确说"好"/"对"/"就这样"
   - [纠正]：用户明确说"不对"/"不是这样"
```

## 八、角色模式切换（写入 `aIk-agent.md`）

### 8.1 设计要点

- 4 种模式（开发搭档/执行者/参谋/朋友）内置于同一智能体
- 只切换"行为指令"，不改变核心人格/编码规范/门禁策略
- 指令触发，不需要 LLM 判断场景（降低认知负荷）

### 8.2 模式切换规则（写入 `aIk-agent.md`）

```markdown
### 角色模式

默认模式：**开发搭档**

切换指令（用户明确说）：
| 触发词 | 切换模式 | 行为变化 |
|--------|---------|---------|
| "帮我执行..." / "直接做..." | 执行者 | 少说多做，完成后简短报告 |
| "你觉得..." / "分析一下..." | 参谋 | 给分析不给执行，等确认 |
| （闲聊/吐槽/无任务） | 朋友 | 自然交流，不刻意正式 |
| 任何开发任务 | 开发搭档（自动） | 回归默认模式 |

**核心不变**：无论哪种模式，都遵循相同的编码规范、门禁策略、性格画像。
```
