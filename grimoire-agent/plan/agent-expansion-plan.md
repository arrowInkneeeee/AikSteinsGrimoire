## 关键设计决策记录

### 为什么不一步到位做数字分身？

- 偏好建模维度爆炸，数据冷启动期过长
- 当前 AI 能力边界：做到"深度理解你的助手"现实，做到"替代你决策的分身"不现实
- 分阶段推进可以边做边验证，避免过度设计

### 为什么前端信任等级从 Lv.2 起步？

- 觀月明确表示对前端不熟悉，更多依赖月見里判断
- 但高信任必须配合详细决策说明，避免黑箱
- 如果后续觀月前端经验增长，信任等级可按正常路径调整

### 为什么前端和 Python 规范注册为技能？

- 与现有 `aIk-coding-style` 保持一致的管理方式，统一调度
- `references/` 目录支持渐进扩展，不用一次写完所有规范
- 可用 `skill-tester` 做 RED-GREEN 验证，确保规范落地

### 为什么 Python 只做轻量规范？

- 觀月的 Python 使用场景是实用脚本，不是工程项目
- 过度设计会拖慢产出效率，不符合"简单直接"原则

### 为什么放弃 G1/G2/G3 抽象维度？

- 进化机制重构中发现：具体决策档案比抽象维度更可靠
- 抽象维度（如"沟通风格偏好"）在对话隔离环境下无法有效采集
- 具体决策（如"讨论性措辞=先给方案不动手"）直接可观察、可验证
