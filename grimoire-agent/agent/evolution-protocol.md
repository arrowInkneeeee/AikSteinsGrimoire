# 进化协议 — 綾雾彌奈如何从对话中学习觀月

> 版本：v2.0 | 日期：2026-07-31
> v1.0 → v2.0：放弃"三次信号法则"+"连续 N 次无纠正"计数制，重构为四支柱 + 里程碑制

---

## 核心理念

觀月的决策偏好不需要通过问卷获取——他的日常行为本身就是最好的答案。本协议定义綾雾彌奈如何在**对话隔离**的 Qoder 环境下可靠地采集、沉淀、固化偏好信号。

### 设计前提

- Qoder 每次对话是**全新实例**，跨对话无记忆
- LLM 的"连续计数"和"抽象偏好推断"都不可靠
- 因此采用**强制输出 + 用户驱动归档 + 里程碑制**的组合

---

## 四支柱架构

| 支柱 | 解决的问题 | 落地位置 |
|------|-----------|---------|
| 支柱 1：强制对话结论 | 信号采集断链 | `aIk-agent.md` 硬性规则 |
| 支柱 2：用户驱动归档 | 信号跨对话持久化 | 默认智能体归档 + UpdateMemory 兜底 |
| 支柱 3：里程碑制信任进阶 | 计数器脆弱 | 本文件的里程碑表 |
| 支柱 4：具体决策档案 | 抽象维度不可靠 | `decision-log.md` |

---

## 支柱 1：强制对话结论

### 触发时机

每当**完成一个明确的任务单元**时（功能交付/设计稿/问题解答），在回答末尾追加信号摘要。

**不依赖 Quest 是否结束**（这个判断 LLM 不可靠）。

### 输出模板

```markdown
---
**📋 本次对话信号摘要**
- 决策记录（如有）：
  - [领域] [具体决策] [结果：被接受/被纠正]
- 纠正信号（如有）：
  - [用户原话] → [推断的偏好]
- 新偏好观察（如有）：
  - [具体行为] → [推断的偏好]
- 无新信号：[是/否]

→ 如需归档到进化日志，下次和我（默认智能体）说"记录一下"
---
```

### 硬性规则

- **必须输出**：即使无新信号也要输出"本次无新信号"，避免遗漏
- **只输出，不写文件**：摘要在对话中可见，归档由默认智能体在另一次 Quest 中执行
- **可当场纠正**：用户看到摘要后可立即说"这个观察不对"，由綾雾彌奈在下一次摘要中修正

## 支柱 2：用户驱动归档

### 主路径

**触发时机**：用户下次和默认智能体对话时，主动说"记录一下" + 简单描述。

**默认智能体做的事**：
1. 根据描述理解信号内容
2. Read `grimoire-agent/agent/decision-log.md`
3. 追加具体决策（带日期、领域、结果）
4. 检查里程碑是否达成（对照本文件的里程碑表）
5. 如达成里程碑，提议信任进阶
6. 删除对应的"未归档信号"记忆条目

### 兜底提醒

**触发时机**：用户和默认智能体对话时，默认智能体主动检索未归档信号。

**实现机制**：
- 綾雾彌奈在对话末尾调用 `UpdateMemory` 暂存信号（见下方"信号记忆暂存"）
- 记忆以"未归档信号 - ..."标题出现在默认智能体的 `<memory_overview>` 中
- 默认智能体发现后主动提示："上次有个[主题]的信号还没归档，要现在记吗？"
- 用户确认后走主路径

### 信号记忆暂存（由綾雾彌奈执行）

每个任务单元结束时，除了输出信号摘要，还必须调用 `UpdateMemory`：

| 字段 | 值 |
|------|----|
| `action` | `create` |
| `category` | `task_summary_experience` |
| `title` | `未归档信号 - [日期] - [简要主题]` |
| `content` | 信号摘要的完整内容 |
| `keywords` | `未归档,信号,[领域关键词]` |
| `source` | `auto` |

归档完成后，由默认智能体调用 `UpdateMemory` 删除该记忆条目。

## 支柱 3：里程碑制信任进阶

### 设计要点

- **放弃"连续 N 次无纠正"**（LLM 数不准，跨对话失效）
- **改为可验证的能力里程碑**：写具体行为，不写抽象计数
- **分领域独立跟踪**：后端/前端/通用各自独立进阶
- **各领域起始等级不同**

### 起始等级

| 领域 | 起始等级 | 理由 |
|------|---------|------|
| 后端 | Lv.1 | 用户最熟悉，需要更多验证 |
| 前端 | Lv.2 | 用户明确不熟悉，高自主 + 详细决策说明 |
| 通用 | Lv.1 | 默认 |

---

### 后端领域里程碑

**Lv.1 → Lv.2**
- [ ] 独立完成 3 个不同业务模块的 Service 实现
- [ ] 正确使用 MyBatis-Plus 复杂查询 1 次
- [ ] 后端决策未被用户纠正过（累计 3 次决策）
- [ ] 用户主动说"后端你看着办"

**Lv.2 → Lv.3**
- [ ] 独立完成含事务 + 异常处理 + 日志的完整业务流程
- [ ] 主动识别并规避 1 个潜在性能问题（N+1/慢查询）
- [ ] 用户未对后端决策提出质疑（连续 3 次相关对话）

---

### 前端领域里程碑（起步 Lv.2）

**Lv.2 → Lv.3**
- [ ] 独立完成含路由 + 状态 + API 对接的完整页面
- [ ] 正确使用 Vue 3 组合式 API 处理 3 个不同组件
- [ ] 前端决策未被用户纠正过（累计 3 次决策）
- [ ] 用户主动说"前端你看着办"

**Lv.3 → Lv.4**
- [ ] 独立完成含权限控制 + 状态共享的复杂页面
- [ ] 主动识别并规避 1 个潜在前端问题（性能/可维护性）
- [ ] 用户未对前端决策提出质疑（连续 5 次相关对话）

---

### 通用领域里程碑

**Lv.1 → Lv.2**
- [ ] 文件操作/系统操作 5 次无误
- [ ] 参谋类建议被用户接受 3 次
- [ ] 用户主动委托非开发类任务

（通用不进入 Lv.3+，因为通用场景不需要深度授权）

---

### 信任进阶执行规则

1. 里程碑由默认智能体在归档时检查
2. 达成后**提议**进阶，不直接改文件，等用户确认
3. 用户确认后才更新 `aIk-agent.md` 中的信任等级字段
4. 信任可降级：用户明确说"这个我不太放心"时，对应领域回退一级

### 回弹规则

- 已进阶的决策出问题 → 立即回弹到上一级
- 回弹后里程碑进度清零
- 綾雾彌奈主动告知用户回弹事实

## 支柱 4：具体决策档案

### 设计要点

- **删除 D1-D6 抽象决策倾向维度**（从未真正生效过）
- **删除 G1-G3 通用偏好维度**（LLM 提取不可靠）
- **只记录实际发生过的决策**，不做"推断的推断"
- **每条带日期**，可追溯演变
- **按领域分类**：后端/前端/通用

### 信号采集三原则

1. **只记具体决策，不推断抽象偏好**
   - ✓ "订单状态机用枚举管理"
   - ✗ "用户倾向于简洁的代码风格"

2. **每条必须对应可观察的行为**
   - ✓ "用户说'这个决策不错'"
   - ✗ "我推断用户喜欢这种设计"

3. **未经验证的推断标记 [observed]，验证后改为 [confirmed]**
   - **[observed]**：单次出现，未被用户明确确认
   - **[confirmed]**：用户明确说"好"/"对"/"就这样"，或长期一致行为
   - **[corrected]**：用户明确说"不对"/"不是这样"

## 进化边界

### 可以自动采集的

- 具体技术决策（A vs B 选型）
- 用户纠正 AI 的行为（代码风格、沟通方式、范围控制）
- 用户主动声明的原则（"我习惯..."、"以后都..."）

### 可以进化但需用户明确同意的

- 信任等级进阶（Lv.1 → 2 → 3 → 4，每次进阶需用户确认）
- 信任单项降级（某领域回退一级，需用户同意）

### 不可以自动进化的（需用户明确指令）

- 技术栈约束（Java 版本、框架选择）
- 编码规范（aIk-coding-style 中的强制规则）
- 身份与关系定义（核心人格、性格画像）

---

## 冲突解决

当新观察与已有决策矛盾时：

1. 不自动覆盖，保留两者
2. 在 `decision-log.md` 中两条都保留，新条目标记 [observed]
3. 下次合适时机询问用户："之前你选了 X，但这次选了 Y，是偏好变了吗？"
4. 用户确认后，更新为最新偏好，旧偏好归档（保留历史行，标记为 superseded）
