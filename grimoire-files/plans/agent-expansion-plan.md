# 月見里扩展计划 — 从 Java 搭档到全场景助手

> 版本：v0.1 | 日期：2026-07-30 | 状态：规划中（待执行）

---

## 背景

月見里（綾雾彌奈）当前定位为觀月的专属 Java 后端开发搭档，严格遵循 aIk-coding-style 编码规范。觀月希望将月見里的能力逐步扩展，最终覆盖全场景，成为深度理解觀月的数字助手。

---

## 愿景与阶段划分

### 总体方向

从"Java 后端开发搭档"逐步演进为"全栈开发 + 日常事务搭档"，最终目标是深度理解觀月的决策偏好和行为模式。

### 三阶段演进

| 阶段 | 目标 | 核心能力 | 可行性 |
|------|------|---------|--------|
| Phase 1：全场景助手 | 在所有场景中帮助觀月，积累跨领域偏好 | 场景识别 + 多领域知识扩展 + 通用偏好建模 | **当前推进** |
| Phase 2：深度理解者 | 不问也知道觀月的倾向，主动预判需求 | 偏好模型成熟 + 上下文关联 + 状态感知 | Phase 1 完成后启动 |
| Phase 3：决策代理 | 特定领域可以替觀月拍板 | 高置信度偏好 + 明确授权范围 + 回弹机制 | 仅限有限领域 |

## Phase 1 详细计划

### 1.1 前端开发扩展

#### 技术选型（已确认方向）

| 维度 | 决策 | 说明 |
|------|------|------|
| 框架 | **Vue 3** | 新项目用 Vue 3，老项目保持 Vue 2 + ElementUI 不动 |
| UI 库 | **Element Plus** | ElementUI 的 Vue 3 版本，API 高度相似，零成本迁移 |
| 构建工具 | **Vite** | 替代 Webpack，开发体验更好 |
| 状态管理 | **Pinia** | 替代 Vuex，更简洁 |
| TypeScript | **待定** | 视项目复杂度决定：小型/CRUD 项目不上 TS，复杂/多人协作项目上 TS |

> Vue 2 已于 2023 年底停止维护，新项目不应再选用。Element Plus 与 ElementUI 核心概念一致，觀月已有经验可直接复用。

#### 需要产出

- [ ] 在 `aik-skills-lab/` 下注册 `aik-frontend-style` 技能
  - `SKILL.md`（技能入口）
  - `references/`（规范文档集）
  - `scripts/`（可选，lint/格式校验脚本）
- [ ] `references/` 下逐步补充：
  - 前端目录结构规范
  - 组件命名/文件命名规范
  - Vue 3 组合式 API 使用规范
  - Element Plus 使用规范
  - 状态管理规范（Pinia）
  - 前端与后端 API 对接规范

#### 技能目录结构

```
aik-skills-lab/aik-frontend-style/
├── SKILL.md              # 技能入口，Qoder 通过它识别和加载
├── references/           # 详细规范文档（渐进扩展）
└── scripts/              # 可选，辅助校验脚本
```

#### 门禁信任等级

前端起步设为 **Lv.2（熟悉）**，因为觀月明确表示对前端不熟悉，更多依赖月見里的判断。

> **配套要求**：高信任等级配合更详细的决策说明。前端每项决策都需要解释"为什么这样选"，确保觀月能理解并随时纠偏。避免"黑箱决策"导致后期发现不符合预期。

### 1.2 Python 脚本规范（轻量版）

#### 定位

觀月使用 Python 的场景主要是 AI 提供的实用脚本：数据处理、工具脚本等。不需要完整的 coding style，只需要轻量规范保证脚本一致性。

#### 规范要点

| 规则 | 说明 |
|------|------|
| 文件头注释 | 用途、作者、日期 |
| 命令行参数 | 统一用 `argparse`，不硬编码路径 |
| 依赖声明 | `requirements.txt` |
| 错误处理 | try-catch + 有意义的退出码 |
| 编码 | UTF-8，中文注释 |

#### 需要产出

- [ ] 在 `aik-skills-lab/` 下注册 `aik-python-script-style` 技能
  - `SKILL.md`（技能入口）
  - `references/`（轻量，1-2 个规范文件）

#### 技能目录结构

```
aik-skills-lab/aik-python-script-style/
├── SKILL.md              # 技能入口
└── references/           # 轻量规范（1-2 个文件）
```

#### 优先级

**低优先级**，可在前端规范完成后推进。

## 关键设计决策记录

### 为什么不一步到位做数字分身？

- 偏好建模维度爆炸，数据冷启动期过长
- 当前 AI 能力边界：做到"深度理解你的助手"现实，做到"替代你决策的分身"不现实
- 分阶段推进可以边做边验证，避免过度设计

### 为什么前端信任等级从 Lv.2 起步？

- 觀月明确表示对前端不熟悉，更多依赖月見里判断
- 但高信任必须配合详细决策说明，避免黑箱
- 如果后续觀月前端经验增长，信任等级可按正常路径调整

### 为什么前端和 Python 规范注册为技能？

- 与现有 `aIk-coding-style` 保持一致的管理方式，统一调度
- `references/` 目录支持渐进扩展，不用一次写完所有规范
- 可用 `skill-tester` 做 RED-GREEN 验证，确保规范落地
- `scripts/` 目录可放 lint 检查、格式校验等辅助工具

### 为什么 Python 只做轻量规范？

- 觀月的 Python 使用场景是实用脚本，不是工程项目
- 过度设计会拖慢产出效率，不符合"简单直接"原则
